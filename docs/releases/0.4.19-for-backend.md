## Changed in 0.4.6: a real compare loop
- Loop name `compare`: the Designer plans the families (from the request or case, else proposes them from list_plants; confirmed by the user, or recorded as unconfirmed assumptions in auto mode). One nested FamilyDesigner run per family, then the Verifier per feasible design, the Economist ranks (design.comparison), the Explainer writes the comparison. Export md has a "## Comparison" table.
- Optional setting GEOMIND_COMPARE_CONCURRENCY (or CompareLoop(concurrency=)): families run side by side up to that number; unset = one at a time. Mode ask always runs one at a time.
- State: design.alternatives entries {family, design, result, verdict, reason}, verdict in feasible | infeasible | verified | rejected | failed | blocked. design.comparison {by, ranking, recommended}; the recommended design becomes the final design.
- New stop reasons: no_alternatives, no_verified. Budget/time stops give a partial answer listing finished alternatives; budgets cover all parallel families.
- Old run logs with loop `compare` still load and replay through StudyCompareLoop (old driver).

## Changed in 0.4.7
- Budgets now reserve each in-flight model call with a known cap, so parallel compare families no longer pass the token/cost cap (0.4.6 could overshoot, e.g. 89k on an 80k cap).

- estimate_costs case gaps return case_incomplete (paths in error.suggestions), like simulate.
- New offline eval recording for the compare loop (real gemini, scripted model); no API change.

## Changed in 0.4.8
- A nested run (e.g. one compare family) that stops without an answer now says why: new error code nested_stopped with the stop message (step limit, refusal, invalid calls). A crash stays internal (text only in the log). RunResult.message added (already in the shared contract).

## Changed in 0.4.9
- Replay of a stopped run ends as the run did: a waiting run waits again on the same request (its pending tool never runs); budget/time-limit stops keep their reason, message and partial answer; cancelled stays cancelled. Only a log that just ends (crash) replays as cancelled.
- Optional setting GEOMIND_COMPARE_RETRIES (or CompareLoop(retries=N)): a family gemini rejects runs again up to N times with gemini's reason; unset = no retry. Retried names look like <family>_r<n>_. Budget covers retries.
- Eval report runs in parallel (evals report(workers=N), --workers N); no runtime change.

Upgrade from 0.4.6/0.4.7 to 0.4.9+: swap the wheel URL + sha256. New optional settings only (GEOMIND_COMPARE_RETRIES); handle error code nested_stopped where nested-run errors are shown.

## 0.4.10 (package code unchanged; CI and docs)
- HOST NOTE, recommended for the backend workers: set MALLOC_ARENA_MAX=2 in the backend environment (e.g. backend/.env.production or the compose env). geomind runs gemini through worker threads; glibc gives each thread its own malloc arena and a long-running process fragments to about 3.5 GB. With MALLOC_ARENA_MAX=2 the same work stays at 1.0-1.7 GB (peak 2.4 GB) and runs a bit faster. No Python leak (tracemalloc plateau about 380 MB).
- Upgrade from 0.4.9: swap URL + sha256 and add the env var above.

## Changed in 0.4.11
- Optional setting GEOMIND_GEMINI_THREADS (gemini_threads): gemini work (sync tools, studies, simulations, verification) runs in a pool of that many threads. Unset = as before (asyncio.to_thread).
- MALLOC_ARENA_MAX=2 is still the recommended fix. Measured RSS end/peak, same load: none 3.5/3.9 GB; pool of 2 2.3/2.5; MALLOC_ARENA_MAX=2 2.0/2.1; both 2.3/2.5. Use the pool only where the host cannot set the env var.
- Upgrade from 0.4.10: swap URL + sha256; nothing else required.

A model call past the limit is cancelled (new gd.errors.TimeLimitReached) and the run gives its partial answer; an async tool gets a timeout result.
