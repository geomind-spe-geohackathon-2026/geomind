# geomind review (main fcb1450, gemini dev cca153b), 2026-11-01

Read by hand: every gemini tool, the case and store code, verification, the design loop, run routing, the agent declarations and prompts. Tests: `make test-all` 2146 passed and 21 failed on a 4-core machine. All 21 failures are only the 1 s fast-tier budget, and they pass when run alone or with fewer workers. `make lint` is clean.

Severity: **H** = wrong result or integrity hole, **M** = wrong behaviour in a real run, **L** = cleanup.

## A. Bugs in the design loop and routing

1. **H: the design loop takes the oldest user message of the chat as the request.** `geomind/loops/design.py:140, 203, 239` (`first_task`, `answered_task`, `explainer_task`) use `next(item.content for item in context.messages if item.role == "user")`. `context.messages` is the chat history plus the new message (`geomind/run.py:117-118`, `engine/context.py:messages_for`). In any chat with an earlier turn (the backend always passes history), the Designer and the Explainer get the first message of the chat, not the current one. Reproduced: with history `["OLD: what is LCOH?", "NEW: design a plant"]`, `first_task` starts with `OLD: what is LCOH?`. Fix: use the last user message (the run's own message), and add a test with history.
2. **H: an agent can pass verification by weakening the case.** The Designer has `set_case`. Verification judges a run against the state's current case (`verify/design.py:result_off_case` only checks that the run used the current case). So a Designer that removes or loosens a constraint, or drops a service from the demand, gets `passed: true`. Also, `update_state` may patch `/case` directly with no gemini validation (`tools/state.py`, `context/state.py:_validated` is only the pydantic model). Fix: keep the case the user or project gave as `case_origin` (or a hash). Verification fails, with code `case_weakened`, when a constraint, a service or a demand value differs from it without a user answer that approved the change. `update_state` refuses `/case` (only `set_case` writes it), and the Verifier prompt reports every case change.
3. **M: the Coordinator can route to stub loops.** `geomind/prompts/coordination/coordinator.md:23` offers `compare` and `makerchecker`, and `run.py:44-47` builds them, but both raise `NotImplementedYet`. A live "compare A and B" request ends with `not_implemented`. Fix: remove them from the prompt and from the `Route` choices until they are built (or build CompareLoop, below).
4. **M: `Route.brief` is never used.** The Coordinator writes a task text (`agents/coordination/coordinator.py:22`), but nothing reads `route.brief` (`grep` finds no use). The delegate gets the raw message. Either pass it to the loop or agent as its task, or remove the field. Rename it to `task` if kept.
5. **L: resuming a design run forgets `max_rounds`.** `run.py:loop_for` builds `DesignLoop(...)` with the default 5, while `DesignLoop.state_dict()` stores the real value.

## B. Agents can be given tasks they cannot do

6. **M: the Designer is told never to choose what it must choose.** `prompts/design/designer.md:60,63` say `size_plant` uses "the backup policy the request or the case gives" and `optimize` uses "the objective, the variables and the number of evaluations the request or the case gives; never pick them yourself". A case has no backup policy, no objective and no evaluation count, and a normal request gives none. In a live run the Designer will stall, ask the user every time, or break its own rule. The no-defaults rule is for package code, not for agent decisions. Fix: the agent chooses, records each choice as an assumption (`source: agent`, `confirmed: false`, with a one-line reason), and the Explainer reports it. The same applies to the Economist's `count` and `seed` (`economist.md` "never choose them yourself").
7. **M: the Economist cannot compare with the sized start or other topologies.** `loops/design.py:229-233` and `economist.md:4,20,37` ask for this, but the Economist only knows `design.result`. Nothing records the sized start's result, and it has no `size_plant` or `simulate` to make alternatives. It will either skip it or invent references. Fix: the Designer records `design.start_result` (the sized start's whole-year run) and `design.alternatives` (`[{family, design, result}]`), and the Economist compares those. Alternative topologies really belong to CompareLoop.
8. **L: the Verifier LLM adds no check.** After the Verifier the driver calls `verify_design` itself (`loops/design.py:after_verification`), and that decides. The Verifier only runs `check_results` and copies the answer. Either give it a real independent job (item 2: report case changes, a stale result, assumptions that are not confirmed) or drop the call to save tokens.
9. **L: the Explainer has no `read_case`.** It explains a design for a case it cannot read.

## C. Case and run storage

10. **M: an old run can read new case files.** `stored.py:load_run` rebuilds the case from the current `case/<name>` artifacts, and `save_profile` overwrites `<name>.csv`. The run id hashes the file contents (`b801a24`), but the files are not stored per run. `result_off_case` compares only the case dict, so overwriting a file with the same name goes unseen. Fix: store files by content hash (`case/<sha256>`, with the case dict pointing to it), or copy them under `<id>.files/` in `save_run`.
11. **M: a race between parallel tool calls.** `runs.py:simulate` reads the case in a worker thread (`case_of`), and `save_run` later reads `context.problem.case` again (`stored.py:64`). A `set_case` in the same step (the engine runs parallel calls) can make the stored case differ from the one the run used. Fix: `run_plant` returns the case dict it used, and `save_run` stores that.
12. **M: `Requirement.constraint` is a list index.** `context/state.py:17-23`. `set_case` uses an RFC 7386 merge patch, which replaces the whole `constraints` list, so removing or reordering a constraint silently points requirements at the wrong one. Fix: give each constraint an id in the case (ask gemini for an optional `id` on `Constraint`, or match by `{on, quantity, over, when}`).
13. **L: one constraint cannot be added without resending the list.** Same merge-patch limit. Consider JSON Patch ops (geomind already has a subset) for `set_case`, or an `add_constraint` tool.
14. **L: a missing project file is an internal error.** `case.py:128` (`read_bytes`) raises `FileNotFoundError`, and the model reads "internal error". Raise a `ToolError` that names the file.
15. **L: an empty file counts as missing.** `case.py:file_contents` uses `supplied.get(name) or load_artifact(...)`.
16. **L: stale docstring.** `tools/state.py:15` still says a requirement has `metric, target, tolerance`. It is now `constraint`. The model reads this text.

## D. Verdict rules

17. **M: two different feasibility rules.** geomind passes a design when gemini's report passes and also no step failed and every balance holds (`verification.py:93`). `gm.study.minimize` counts a trial as feasible on constraints and failed steps only, with no balances. So `optimize` can return `feasible: true` and the Verifier can still reject it on a balance, sending the loop back for a reason the search never saw. Fix in gemini: one public verdict (for example `report.feasible`, or `gm.evaluate.verdict`) that both `minimize` and geomind use; geomind then keeps no pass rule of its own. Until then, document the difference in the Designer prompt.
18. **L: `compare` parses gemini's table headers.** `study.py:shown_values` takes units from column labels like `"lcts [EUR/MWh]"`. If gemini changes the label format, this breaks with an internal `StopIteration`. Ask gemini for `Comparison.to_dict()` in display units (it is in the gemini requests as item 10).
19. **L: `optimize` with `case.<path>` variables.** The best plant is stored, but a best value of a case variable (for example a price) is not applied to the state's case. A later `simulate` then runs on the old value. Either refuse case variables in the tool, or return them so the Designer sets them with `set_case`.

## E. Tests and speed

20. **M: about 20 fast tests sit at the 1 s budget.** These are `test_assessment`, `test_runs`, `test_results`, `test_study`, `test_verification` and `test_verify`. They simulate the hackathon year, and each `gm.evaluate` call copies the plant. They pass alone and fail under parallel load, so `make test-all` is flaky. Fix: a session fixture that simulates each example once and caches the stored run, and a short-window case (one month) for tool tests. Keep the full year in the slow tier.
21. **L: `optimize` has no timeout.** `minimize` with many evaluations runs in a thread with no `timeout` and no progress events, and the spending cap counts only tokens. Give the study tools a timeout and say so in the result.
